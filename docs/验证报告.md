## 状态含义

`定位候选，CE字节复核通过；业务语义未确认` 表示代码模式和解析位置有证据，名称、参数类型、函数功能尚未确认。`运行时快照语义交叉通过` 表示本局对象数据、列表或时间与 API/其他对象交叉吻合。13 个字段均属于快照交叉；索引、网络编号和位置只保留**初步语义**，未进行移动、网络事件或对象创建销毁实验。结构体成员只有达到快照交叉标准才发布当前偏移。

`rva`/`offset` 为 `null` 的项尚不能作为当前偏移使用。`previous_rva`/`previous_offset` 和 `previous_values` 仅保留历史线索。未通过语义证明的结构操作数不因唯一命中升级为字段偏移。

## 特征码与窗口

`src/signatures.json` 对每个主项列出其全部原始 `source_ids` 与别名。引用指令和可定位目标分别保存前 32 字节、地址处 1 字节、后 32 字节。更新 AOB 通配了 RIP 位移、相对分支立即数及重定位数据，并记录当前映像命中数；这只证明当前版本的匹配情况。

运行时字段的 `runtime_window` 使用实际堆对象地址（例如 `0xB7D47E40 + offset`），不把成员偏移解释为模块 RVA。无可靠当前代码引用时，`updated_aob` 为 `null`。旧引用放入 `historical_reference`，不能据此读取当前字段。

没有可靠引用指令的条目以 `null` 和中文原因保留，未用历史地址的邻近字节假冒当前特征。全局数据窗口来自某一运行快照，不能作为跨局稳定 AOB。

## JSON 兼容变化与构建检查

`offsets.json` 使用 schema 2，`signatures.json` 使用 schema 2。原条目通过 `source_ids` 全量覆盖；重复名称合并到 `aliases`。当前 `rva`/`offset` 允许 `null`，旧消费者必须检查空值并处理别名；`previous_*` 不可作为当前地址回退。新增 `semantic_scope`、`location_kind`、`runtime_window`、`historical_reference` 明确地址类别及证据边界。头文件只生成当前定位常量，移除了未经证明的函数原型和旧固定基址。

构建检查包括 735 项覆盖、别名唯一、JSON 一致性、发布字段的实际对象地址与窗口、已发布 AOB 在本映像中的命中数以及 C++17 头文件编译。具体结果见 `ce-evidence.json` 的 `build_validation`。未确认条目保留在数据库，未因缺少证据而丢失。
